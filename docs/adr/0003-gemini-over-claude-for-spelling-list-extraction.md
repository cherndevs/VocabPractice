# Use Gemini rather than Claude for spelling-list extraction

CHE-19 originally built the extraction proxy against Claude Haiku 4.5, validated by hand against two real worksheets (English and Chinese) with a measured cost of ~$0.003/image. That work assumed an Anthropic Console API key, which requires its own billing setup — a credit card and pay-as-you-go account separate from a Claude.ai Pro/Max subscription. For this project, that separate billing account was a real blocker, not a preference: this is a small personal side project, and standing up a second billing relationship for a feature that costs cents was more friction than the feature was worth.

There is no supported way around this by reusing a Pro/Max subscription instead — a Claude.ai subscription authenticates the Claude apps (claude.ai, Claude Code) and isn't a general-purpose API credential; there's no mechanism to point the Messages API SDK at a subscription login, and repurposing one would be outside what the subscription is licensed for.

Google's Gemini API has a free tier (Google AI Studio) that needs only a Google account — no card, no separate billing setup — so it directly removes the actual blocker. Before switching, we re-ran the same validation used for Claude: both test worksheets (English and Chinese) were sent through `gemini-3.6-flash` with an equivalent structured-output request, and both came back with every word extracted correctly, including 考一考 — the exact word Claude had originally misread as its homophone 烤一烤 before the pinyin-ignoring rule was added to the prompt. Accuracy is not the tradeoff here.

Cost is. Gemini 3.6 Flash is a "thinking" model — hidden reasoning tokens are generated alongside the visible answer and billed at the output rate ($7.50/M, versus $1.50/M input). Measured against the same two worksheets, actual cost came to roughly $0.005–$0.014/image depending on how much the model reasoned — noticeably more than Claude's flat $0.003, and less predictable, since it varies with the input rather than being a fixed per-call cost. This only matters once free-tier usage is exceeded. The free tier's rate limit (1,500 requests/day) is far beyond what a personal app photographing worksheets will ever hit, so in practice this project pays nothing, and the cost comparison above is recorded for if that ever changes rather than as a current concern.

The architecture from [0002](0002-server-proxy-for-image-extraction-no-persistence.md) is unaffected: the extraction call still happens through a stateless server-side proxy, the key still lives in a Render environment variable and never reaches the browser, and nothing is persisted. Only the provider, the model name, the request/response shape, and the env var name (`GEMINI_API_KEY` in place of `ANTHROPIC_API_KEY`) changed.

## Considered Options

- **Claude Haiku 4.5 via Anthropic Console API key** (original CHE-19 build) — rejected: requires a separate billing account, which was the actual objection for this project, not the per-image cost.
- **Reusing an existing Claude.ai Pro/Max subscription for API calls** — not viable: no supported mechanism exists to authenticate the Messages API with a subscription login rather than a Console API key.
- **Gemini 3.6 Flash via Google AI Studio free tier** (chosen) — no billing account needed, accuracy validated equal to Claude on both test worksheets, free-tier volume far exceeds this app's real usage. Real per-image cost if ever billed is higher and less predictable than Claude's, due to billed thinking tokens — accepted as a non-issue at this app's scale, revisit only if usage ever approaches the free-tier ceiling.
